# tenji-online

点字（日本語点字）を学ぶためのクイズアプリです。`index.html` 1枚だけの静的サイトで、ビルド不要です。

- **ひとりで練習**: 点字訓練・単語・文章・数字・読みの5モード。点字マスをタップして回答します。点字訓練モードは社会福祉法人名古屋ライトハウス「点字一覧表」の五十音（長音符・促音符含む）・濁音・半濁音・拗音・特殊音（ティ/ファ/テュ/イェ等）に掲載されている142文字・組み合わせをちょうど一通り出題します。
- **みんなで対戦**: ホストが自分でルームコードを決めて共有し、同じ問題に複数人で挑戦。
  - お題モード（単語/文章/数字/読み）と問題数（5/10/15問）はルーム作成後、ロビー画面でホストが選びます。参加者の画面にも選んだ内容がリアルタイムで反映されます。
  - 単語/文章/数字モードは「1文字ごと」に正解した分だけ得点が入ります（速さボーナスは単語全体の完答スピードで決まる満点に、正解した文字の割合をかけたもの。即答で100点、時間切れ間際で50点に近づく満点、不正解の文字は0点）。読みモードは全体が合っているかどうかで判定します。
  - タイマーバー上に誰がいつ回答したかがリアルタイムで表示され、結果発表で正解/不正解の色に変わります。
  - ゲーム開始時は「よーい、スタート」のカウントダウンが入ります。
  - 全員が回答し終わったら（またはタイマーが切れたら）自動で結果発表に切り替わり、カウントダウン後に次の問題へ自動で進みます。ホストが毎回ボタンを押す必要はありません。
  - 最終結果画面でホストが「もう一度プレイ」を選ぶと、同じルームコードのままロビーに戻って何度でも対戦できます（新しいルームを作る必要はありません）。
  - ロビー画面で、ホストは参加者を「キック」したり「部屋を削除」したりできます。ゲストは「退場する」でいつでも抜けられます。
  - ロビーで90秒間ゲームが開始されないと自動でルームが解散し、同じルームコードがすぐに再利用できるようになります。また、ホストがタブを閉じる/通信が切れるとロビー中のルームは自動で解散し、各参加者も自分のタブを閉じると参加者一覧から自動的に消えます（Firebaseの`onDisconnect`機能による）。

オンライン対戦は Firebase Realtime Database + 匿名認証を使っています。

## デプロイ

`index.html` をそのまま GitHub Pages や Netlify に置くだけで動きます（ビルドステップなし）。

## Firebase の設定（オンライン対戦を使う場合に必要）

`index.html` の `<script type="module">` 内、`firebaseConfig` のところに自分の Firebase プロジェクトの設定を貼り付けます（既存の `tenji-game` プロジェクトをそのまま使う場合はこの手順は不要です）。

1. [Firebase Console](https://console.firebase.google.com/) でプロジェクトを作成（または既存のものを使う）。
2. **Authentication** → Sign-in method で **匿名（Anonymous）** を有効化。
3. **Realtime Database** を作成。
4. プロジェクト設定 → マイアプリ → ウェブアプリを追加し、表示される `firebaseConfig` を `index.html` に貼り付け。

### Realtime Database のセキュリティルール

Realtime Database → ルール タブに、以下を貼り付けて公開してください（**重要**: これを設定しないと初期状態のテストモードルール期限切れ等で書き込みができなくなります）。

```json
{
  "rules": {
    "rooms": {
      "$roomCode": {
        ".read": "auth != null",
        ".write": "auth != null && (!data.exists() || data.child('hostUid').val() === auth.uid || (data.hasChild('createdAt') && (now - data.child('createdAt').val()) > 21600000))",

        "players": {
          "$uid": {
            ".write": "auth != null && auth.uid === $uid"
          }
        },
        "questionsProgress": {
          "$qIndex": {
            "answers": {
              "$uid": {
                ".write": "auth != null && auth.uid === $uid",
                ".validate": "newData.child('uid').val() === auth.uid"
              }
            }
          }
        }
      }
    }
  }
}
```

**既存のプロジェクトをお使いの場合は、上記の最新版に貼り替えてください。** 以前のバージョンには `root.child(...).val() === $qIndex` という、ルームの現在の問題番号（数値）とURLのパス部分から取れる `$qIndex`（文字列）を比較する条件が入っていましたが、Realtime Databaseのルール内ではこの2つの型が一致せず、ホスト以外（ゲスト）の回答の書き込みが常に`permission_denied`で失敗していました。ホストは別の経路（ルーム本体への書き込み権限）でたまたま許可されていたため、ホストだけ正常に動いて見えていました。

**さらに新しいバージョンでは、ルームコードの再利用に関する条件を変更しています。** 以前のルールはルーム本体の書き込みを「まだ存在しない」か「自分が元のホスト」かのいずれかにしか許可しておらず、アプリ側だけで「ゲームが始まったルームは別の人が再利用してよい」と判定していました。この判定はセキュリティルールに反映されていなかったため、実際には**自分以外が作ったルームコードの再利用は常に`permission_denied`で失敗していました**（同じコードを別の人・別のブラウザ・別の匿名アカウントで使おうとすると、画面には「ルームを作成できませんでした。Firebaseのセキュリティルールが正しく設定されているか確認してください。」と表示されます）。さらに、その判定基準自体（「ロビーを抜けたら再利用可」）には、元の参加者がまだそのルームに繋がったまま別ゲームのデータで上書きされてしまう、という安全性の問題もありました。

そのため新しいルールでは「自分が元のホストである」か「作成から6時間以上経っている（放置されたルーム）」場合のみ、別の人による上書きを許可するようにしました。通常のルームコード解放は次の仕組みで行われ、こちらは実際にルームを削除するので安全です:

- ホストがロビー画面で「部屋を削除」を押す。
- ロビーでゲームが90秒間開始されないと自動で解散する。
- ホストがタブを閉じる/通信が切れる（`onDisconnect`）とロビー中のルームが自動で解散する。

このルールの考え方:

- ルーム本体（`status`/`currentQuestionIndex`/`questionStartedAt`/`questions` など）はホストの uid だけが書き込めます（放置されたルームの上書きを除く）。
- 各プレイヤーは自分の `players/{uid}`（名前・スコア）と、自分の回答（`questionsProgress/{問題番号}/answers/{uid}`）だけを書き込めます。正解判定・スコア計算は各プレイヤーが自分のブラウザで行い、自分のデータとして書き込む方式なので、「ホストだけが採点する」ための特別な権限は不要です。
- ルームを読めるのは「ルームコードを知っている人」全員です。

### ルームコードについて

ルームコードはホストが自分で決めます（重複していれば作成時にエラーになるので別のコードを選んでください）。パスワードはなく、ルームコードを知っている人なら誰でも参加できます。授業や友人同士などカジュアルな利用を想定しているための仕様です。誰にも知られたくない場合は、推測されにくいコードを選んでください。
